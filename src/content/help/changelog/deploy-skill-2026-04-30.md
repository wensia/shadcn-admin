# 更新历史：部署流程 Skill 化

## 变更概览

生产部署流程从“记住并直接运行脚本”调整为“先触发项目 Skill，再按部署范围执行预演、确认、部署和验证”。

## 新增内容

| 项目 | 内容 |
| --- | --- |
| Skill | 新增 `$ruimf-deploy` 项目部署 Skill |
| 位置 | `.agents/skills/ruimf-deploy/SKILL.md` |
| 前端执行器 | `deploy-frontend.sh` |
| 后端执行器 | `deploy-backend.sh` |
| 适用范围 | 前端部署、后端部署、全量部署、健康检查、部署故障排查 |

## 使用方式

以后需要发布生产环境时，优先向 AI 助手说明部署范围，例如：

```text
使用 $ruimf-deploy 部署前端
使用 $ruimf-deploy 部署后端
使用 $ruimf-deploy 做一次全量发布预演
```

Skill 会先确认部署范围和当前工作区状态，再决定是否执行 dry-run、是否需要数据库备份、是否需要用户确认。

## 关键规则

- 前端仍然采用本地构建后上传 `dist/` 的方式。
- 后端部署默认必须备份数据库，并在服务恢复后执行数据库迁移。
- 全量部署按后端优先、前端随后发布的顺序执行。
- 脚本仍保留，但作为 Skill 的执行器使用，不再作为唯一流程入口。

## 影响

该变更主要面向管理员和开发维护人员，不影响普通员工使用 CRM。
